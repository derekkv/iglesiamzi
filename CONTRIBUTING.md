# Contribuir a iglesiamzi

Gracias por ayudar a mejorar este proyecto para las iglesias, congregaciones y
ministerios que lo utilizan.

## Condiciones legales

Al enviar código, documentación, diseños, pruebas u otros cambios al repositorio,
aceptas que tu contribución se incorpore y distribuya conforme a la
[Licencia Comunitaria de Software para Iglesias — Ecuador](LICENSE).

Debes enviar únicamente material que hayas creado o que tengas derecho a
compartir. No incluyas código, imágenes, fuentes, datos, secretos ni otros
materiales de terceros cuya licencia sea incompatible con la licencia del
proyecto.

Cada contribuyente conserva los derechos que legalmente le correspondan sobre
su aporte, incluidos los derechos morales reconocidos por la legislación
aplicable, y concede los permisos descritos en la sección 7 de `LICENSE`.

## Certificación de origen

Este proyecto utiliza la certificación `Signed-off-by`, basada en el Developer
Certificate of Origin 1.1. Al firmar un commit, certificas que:

1. Creaste la contribución, total o parcialmente, y tienes derecho a enviarla
   bajo la licencia del proyecto; o
2. La contribución se basa en trabajo anterior que, según tu conocimiento, está
   cubierto por una licencia compatible y tienes derecho a enviarla; o
3. Recibiste la contribución de otra persona que certificó una de las opciones
   anteriores y no la modificaste de manera incompatible; y
4. Entiendes que la contribución y la información de autoría asociada quedarán
   registradas públicamente y podrán conservarse indefinidamente en el historial
   del proyecto.

Firma tus commits mediante:

```bash
git commit -s -m "Descripción clara del cambio"
```

Esto añade una línea como la siguiente al mensaje del commit:

```text
Signed-off-by: Nombre Apellido <correo@example.com>
```

La firma debe usar tu nombre real o una identidad que estés legalmente
autorizado a utilizar. No firmes en nombre de otra persona sin autorización.

## Antes de enviar cambios

1. Crea una rama específica para el cambio.
2. No incluyas contraseñas, claves de API, tokens, datos personales reales ni
   archivos `.env`.
3. Mantén el cambio enfocado y documenta su finalidad.
4. Verifica que el proyecto compile y que las funciones afectadas sigan
   funcionando.
5. Describe cualquier migración, cambio de configuración o efecto sobre datos.
6. Confirma que todos tus commits tengan la línea `Signed-off-by`.

## Pull requests

La descripción del pull request debe indicar:

- qué problema resuelve;
- qué archivos o módulos modifica;
- cómo se verificó el cambio;
- si requiere migraciones o nuevas variables de entorno;
- si trata datos personales o modifica permisos de acceso; y
- qué iglesia o caso de uso se beneficia, sin divulgar información confidencial.

El envío de un pull request no garantiza su aceptación. El Titular o las
personas mantenedoras pueden solicitar cambios, rechazar la contribución o
cerrarla si no es compatible con la finalidad, seguridad o licencia del
proyecto.
